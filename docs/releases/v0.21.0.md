# Homelab Dashboard v0.21.0

v0.21 turns the Update Manager into an opt-in maintenance and recovery system instead of only an update checker/button surface.

## Highlights

- Adds optional **scheduled service updates** with configurable maintenance days and start/end times.
- Adds global and per-service **release delays** so a newly detected release can age before unattended installation.
- Adds per-service policies: **Use global policy**, **Manual**, **Scheduled**, and **Monitor only**.
- Scheduled maintenance updates services **sequentially** and stops after the first failure by default.
- Adds automatic Docker Compose/Dockge management-provider suggestions when a card exactly matches a discovered Compose service. The user must still approve the match.
- Captures meaningful HTTP/rich-integration health before a service update and verifies those same signals afterward.
- Adds capability-aware rollback metadata and manual-recovery guidance.
- Docker Compose/Dockge keeps the previously running image available until Dashboard-level verification succeeds and can restore that image after a failed verification when rollback is enabled.
- Before a supported host update, Dashboard records which other monitored services are healthy; after the host returns, it checks whether those services recovered.
- Update history identifies scheduled maintenance and preserves failure/recovery guidance.

## Safe defaults

Scheduled installation is **off by default**. Existing manual update behavior continues to work without configuring a maintenance schedule.

Host-level updates remain deliberately separate: TrueNAS System updates still require explicit Owner/Admin confirmation and are never included in Update All or scheduled service maintenance.

## Rollback scope

Rollback is provider-specific. Docker Compose/Dockge supports restoring the previously running **container image**. That does not automatically rewind persistent volumes, application databases, or migrations performed by the new application version. Services with potentially incompatible data migrations should use a Manual rollback policy plus an appropriate platform/application backup or snapshot strategy.

TrueNAS Apps do not advertise automatic rollback in this release. TrueNAS System reports a manual recovery path rather than automatically changing boot environments.

## Post-host recovery

For a TrueNAS System update, v0.21 records other enabled HTTP-monitored services that were healthy before the reboot. After TrueNAS returns on the expected version, Dashboard waits for those services to recover. A host update can still succeed while clearly reporting services that remain unavailable and need attention.

## Upgrade

No Compose, environment-variable, credential, or manual database changes are required. SQLite migrations for the new policy/history fields are automatic. Preserve `/app/data` as usual. See `docs/UPGRADE-v0.21.md`.
