# Homelab Dashboard v0.20.3

v0.20.3 improves service monitoring in homelabs where the URL a person opens is not the best network path for the Dashboard backend.

## Highlights

- Adds an optional **Internal / monitoring URL** to every service card.
- Keeps the **Browser URL** unchanged as the address opened by the card.
- Health checks and supported rich integrations use the internal URL when configured, then fall back to the Browser URL when it is blank.
- Supports direct LAN IPs, Docker DNS/service names, and other backend-reachable private routes.
- Full dashboard layout export/import and page cloning preserve internal monitoring URLs.
- Shareable page-template packs intentionally omit environment-specific internal addresses.
- Adds networking guidance for split DNS, Docker `extra_hosts`, Tailscale/private-overlay remote access, and troubleshooting false Offline states.

## Why this matters

A service may be online and reachable from a user's browser while the Dashboard container cannot follow the same reverse-proxy, public-DNS, hairpin-NAT, or Tailscale path. v0.20.3 lets the user keep a convenient remote/browser URL while monitoring locally over the most reliable route.

Existing services require no migration work. Their Internal / monitoring URL starts blank, which preserves the previous behavior.
